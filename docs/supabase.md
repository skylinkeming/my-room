# 日日小屋：開啟兩支手機同步

未設定時，三個功能使用瀏覽器 localStorage，重新整理會保留；不同手機不會同步。無痕模式、清除網站資料或換瀏覽器可能失去紀錄，請在「名字與同步設定」下載 JSON 備份。

## 建立專案

1. 到 https://supabase.com 建立免費專案，記下資料庫密碼。
2. 在專案 SQL Editor 貼上並執行本 repository 的 `supabase/setup.sql` 全文。請確認執行成功。
3. 在 Project Settings → API / API Keys 找到 Project URL 及 **publishable key**（或舊版 anon key）。請勿使用 secret key、service_role key 或資料庫密碼。
4. 開啟日日小屋 → 任一生活功能 →「名字與同步設定」，輸入你的名字、Project URL、公開金鑰，按「建立共同小屋並上傳本機資料」。
5. 等待「已同步」，按「複製小屋邀請連結」，私下傳給另一半。
6. 另一半用自己的手機開啟連結、確認加入，再設定自己的名字。加入時不會把原本本機資料混入新小屋；切換前會留存最多三份本機備份。
7. 用兩台手機各新增一則留言、勾選事項、決定一道餐點，確認另一台約 8 秒內出現，重新整理後仍在。

沒有 Supabase 專案也可以完整使用本機功能。這份程式包含串接與 SQL；尚未連線到實際專案驗證。

## 同步方式與權限

- 邀請連結包含 256-bit 隨機小屋密鑰，放在 URL fragment，資料庫只保存其 SHA-256。公開 API key 本身不授予小屋資料存取權。
- **持有完整邀請連結即可讀寫及刪除該小屋所有資料。** 適合可信任的兩人使用，不設個別帳號或角色。不要公開分享連結、截圖或備份；更換公開 key 不等於撤銷邀請。
- 原始資料表開啟 RLS，anon/authenticated 無直接讀寫權；僅能透過指定 RPC，驗證小屋密鑰後操作。
- 離線變更會留在本機待送佇列，上線後重試。操作 ID 避免重複新增；欄位合併保留並行修改、已讀紀錄合併；同欄位以伺服器最後接受的修改為準。刪除後不會被舊裝置復活。
- 不需要開啟 Realtime。頁面可見時每 8 秒檢查，手動操作會立即嘗試送出。
-「中斷同步」僅移除這台裝置的連線資料，保留本機內容，不會刪除雲端資料或撤銷其他裝置。
- 若邀請外洩：備份資料，讓雙方中斷同步，建立全新共同小屋並重新邀請。在 Supabase Table Editor 刪除舊的 `little_home_spaces` 對應列（子資料會連帶刪除）。確認新資料完整後再刪除舊小屋。
- JSON 備份含內容與待送操作，不包含雲端邀請密鑰。匯入前會下載原資料；匯入內容使用新 ID，以避免舊的刪除標記影響還原。

## 可選建置設定

可複製 `.env.example` 為 `.env.local`，填公開網址及 key 預填設定表單；也可直接在畫面輸入。GitHub Pages 使用 Actions 建置，若需預填，可在 workflow build step 的 env 配置對應變數。**VITE_ 變數會包含在公開前端，絕不可放私密金鑰。** 邀請密鑰不放在建置變數。

## 排錯

- 找不到同步功能：確認在正確專案完整執行 SQL。
- 連線未獲允許：檢查 Project URL、publishable/anon key 及 RPC grant。
- 邀請無效：重新複製完整連結，確認專案未暫停、資料庫仍有小屋資料。
- 同步暫停：本機資料仍在，先下載備份，檢查網路後按重試。免費專案若暫停，請在 Supabase 後台恢復。
